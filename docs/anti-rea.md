# Anti-REA 기획 문서

## 큰 그림

후보 04 Anti-REA(AI가 소스 없이 앱을 복제하는 것을 방어)에서 출발해, "방어(난독화)"로 범위를 좁힌다.
내 코드를 읽기 어렵게 꼬아서 사람·AI가 분석하기 힘들게 만든다.

한 줄 요약: **"보호 전엔 코드가 술술 읽히는데, 난독화 후엔 막힌다"**

## 왜 난독화로 정했나

- 쉬움 → "뭔가 돌아간다"는 성공 경험을 빨리 얻는 손풀기용
- before/after가 아주 선명 → 발표용으로 시각 효과 좋음
- 내 코드를 내가 보호하는 거라 안전 (남의 것을 공격하는 게 아님)

## 솔직한 한계 (발표 각도 잡을 때 기억)

- 난독화 도구는 이미 흔해서 "기존 거 쓴 거 아님?" 질문이 나올 수 있음 → 측정 하네스(metrics.py, ai.py)를 직접 만들었다고 답한다.
- "완벽 방어"는 없음 → 성과는 "분석을 얼마나 어렵게/비싸게 만들었나"로 말해야 한다.
- 여유되면 나중에 **워터마킹 추적**(복제범 역추적)을 얹으면 차별점이 생긴다 ← 보류 카드.
  앞선 평가에서 6명 모두 "재구현에는 살아남지 못한다"고 지적했으므로, 얹을 때는 그 한계를 먼저 밝힌다.

## 구조

```
원본 코드 (samples/target.py)
      │
      ▼
 obfuscate.py   이름 치환 · 주석/docstring 제거 · 문자열 인코딩
      │
      ├────────────▶ metrics.py   이름 가독성 · 복잡도 · 주석 비율 (전/후 수치)
      │
      ▼
 ai.py           LLM에게 "이 코드가 뭘 하는지 설명해봐" → 원본 설명과 비교해 정답률 점수화
      │
      ▼
 main.py (Streamlit)   좌: 원본 / 우: 난독화 / 하단: 지표 + AI 분석 before&after
```

핵심 지표: **AI가 보호 전엔 설명에 성공하고, 보호 후엔 얼마나 틀리는가.**

## 연습에서 뺀 것

- 안티디버깅·Frida 탐지: 분석 회피 기술이라 민감하고 저수준이라 시간이 많이 든다. 다루더라도 개념 설명까지만 한다.

## 브랜치 분배

CLAUDE.md 규칙(1 브랜치 = 1 담당, main은 PR로만, Squash and Merge)에 맞췄다.
병렬로 진행하려면 함수 시그니처를 먼저 합의해야 해서 계약 브랜치를 맨 앞에 둔다.

| 순서 | 브랜치 | 내용 | 파일 |
| --- | --- | --- | --- |
| 0 | `docs/anti-rea` | 지금 작업 중인 기획 문서 | `docs/anti-rea.md` |
| 1 | `feat/contract` | 함수 시그니처와 샘플 대상 코드 (작게, 먼저 머지) | `src/obfuscate.py`, `src/metrics.py`, `src/ai.py` 껍데기, `samples/target.py` |
| 2 | `feat/obfuscator-core` | `ast` 기반 이름 치환, 주석 제거, 문자열 인코딩 | `src/obfuscate.py`, 테스트 |
| 3 | `feat/metrics` | 이름 가독성, 순환 복잡도, 주석 비율 | `src/metrics.py`, 테스트 |
| 4 | `feat/ai-analyzer` | LLM 분석 호출과 원본 대비 점수화 | `src/ai.py`, `.env.example` 갱신 |
| 5 | `feat/ui-compare` | 좌우 비교와 before/after 패널 | `src/main.py`, `src/components/` |
| 6 | `feat/ci-report` | PR마다 pytest와 난독화 리포트 아티팩트 생성 | `.github/workflows/` |

- 2, 3, 4는 서로 독립이라 동시에 진행할 수 있다. 5는 껍데기 시그니처만 알면 가짜 데이터로 시작할 수 있다.
- 머지 순서: 0 → 1 → (2, 3, 4) → 5 → 6.
- 4의 API 키는 `.env`에 두고, `.env.example`에는 이름만 추가한다.

## 발표 각도 (꼭 기억할 것)

Python은 바이트코드를 디컴파일하기 쉬워서 난독화 효과에 구조적 한계가 있다. 연습용으로는 괜찮지만,
발표에서는 "차단"이 아니라 **"분석 비용·정확도 저하"**라고 말해야 한다.
안티디버깅과 Frida 탐지는 개념 설명까지만 한다. 워터마킹은 보류 카드로 남겨둔다.
